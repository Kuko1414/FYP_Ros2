## 1. Overview

This is a workspace for a wheeled robot design.

The desired functionality of this workspace is to design a path planning program that uses ROS2 and VLM to access API data to obtain path points and thereby control the movement of the wheeled robot. The robot should be able to plan a path from a starting point to a destination point, and then follow that path. The robot should also be able to detect obstacles in its path and re-plan accordingly.

## 2. Process

To achieve this powerful function, the design concept is as follows， ONLY WHEN IT IS PERMITTED TO PROCEED TO THE NEXT STEP CAN THE SUBSEQUENT FUNCTIONS BE WRITTEN。

  **Step 1.** Firstly, design a preliminary function: create a Python node named "Generate_Path", which, upon receiving the starting point and the ending point, can generate several path points. The path shapes include but are not limited to: straight line, semi-circle, polynomial curve, S-shaped, etc. Then design another Python node named "Track_Path", which, upon receiving the path points sent by "Generate_Path", first stores one as the ideal trajectory, and then plans the speed based on the path points and sends it to the car, allowing the car to navigate based on different paths. The final effect is: after starting both nodes, "Generate_Path" at the terminal asks us to input coordinates and shapes, such as inputting: 1.0 3.0 Semicircle, then it can plan several semi-circle trajectory points, and after publishing this topic, the Track_Path node will walk according to the current path points.

  **Step 2** AFTER ACHIEVING THE ABOVE FUNCTIONS, the ideal path points stored and the actual path points of the moving vehicle are subtracted from each other, and this difference is named as the deviation. However, to avoid over-correction, the frequency is set at 10Hz. At this time, a decision layer needs to be designed: when the deviation is less than 0.1, the vehicle will move normally according to the path points; when the deviation is between 0.1 and 0.5, the PID algorithm is used to correct the deviation of the vehicle, allowing it to return to the ideal trajectory; when the deviation is greater than 0.5, the vehicle stops and re-plans the path based on the current position and the previous destination. The final effect is that after receiving the destination, the vehicle can walk to the destination in a very smooth process, and the average error should remain at a relatively low value.

  **Step 3** AFTER ACHIEVING THE ABOVE FUNCTIONS, we added a depth camera, which can capture images of the front of the vehicle and the distance between the object and the vehicle. When the vehicle is traveling on a path without any obstacles in front of it, the above functions are still used. However, if an obstacle appears in front (for example, detecting an obstacle 0.3 meters in front of the vehicle), a copy of the front image is saved in /src/image, and based on the walkable area feedback from the depth camera, a path to avoid the obstacle and proceed is planned. The ultimate goal is: I place an object 1 meter away from the vehicle as an obstacle. The vehicle should stop at approximately 0.3 meters and plan a route to avoid the obstacle and go around it.

  **Step 4** AFTER ACHIEVING THE ABOVE FUNCTIONS, an MCP structure needs to be added, mainly to assist the robot in accessing Gemini through the API. After setting up the interface, the front image is sent to Gemini, which returns a series of path points. These points are then sent to the Track_Path of the vehicle, allowing the vehicle to follow the path points given by Gemini for navigation. This enables more flexible route and obstacle recognition. For example, if the obstacle ahead is a cave, after recognition, it can attempt to pass through. The ultimate goal is: during the normal operation of the vehicle, when there is an obstacle within 1 meter in front, the collected image and distance are sent to Gemini, which returns a series of path points in pixel units. Then, it is sent to a new Python node named Image Conversion, which converts the pixel-coordinates points into actual path points in meters, and sends them to Track_Path for tracking.
